## Blockers

### QA-022: Confirming a reservation crashes the storefront, so the customer never sees their booking reference or access code; manage booking, check-in and flight status crash too
- **Area:** storefront
- **URLs:** `/`, `/manage-booking`, `/check-in`, `/status`
- **Steps:**
  1. On `/`, search JFK→BOS on 2026-11-07 with 1 adult + 1 child. Select AV 101, fill in both travellers, click **Hold fare for 2 travelers**, then **Confirm reservation**.
  2. In the same browser, open `/manage-booking`, type the booking reference (saved in localStorage) and click **Retrieve**.
  3. On `/status`, enter flight 101 and date 2026-11-07, then click **Check status**.
- **Expected:**
  - Step 1 shows the confirmation with the booking reference and the one-time access code.
  - Step 2 shows the booking.
  - Step 3 shows the flight's status.
- **Actual:**
  - Every step replaces the whole page with "This page couldn't load. Reload to try again, or go back." The page error is `TypeError: Invalid option : option`. Same result at 1440 and 390.
  - Step 1 still creates the booking (five pending bookings now exist: 865CD0, 3AF454, D6CD29, 207412, 69A381), but the customer never sees the reference or the access code.
  - With no SMTP (QA-006) and no operator re-issue (QA-026), the customer can't manage, cancel, check in or pay for the booking.
- **Cause:** `localTime()` calls `new Intl.DateTimeFormat('en-US', { timeZone, dateStyle: 'medium', timeStyle: 'short', timeZoneName: 'short' })`. `dateStyle`/`timeStyle` can't be combined with `timeZoneName`, so it throws. The `catch` repeats the same invalid options, so it throws again. Reproduced in Node:

  ```js
  new Intl.DateTimeFormat('en-US', { dateStyle: 'medium', timeStyle: 'short', timeZoneName: 'short' })
  // → TypeError "Invalid option : option"
  ```
- **Likely files:**
  - `features/storefront/components/FlightShop.tsx:67-71` (`localTime`)
  - `features/storefront/components/FlightStatusSearch.tsx:48-51`
  - **Fix direction:** use explicit `year/month/day/hour/minute` fields with `timeZoneName`, or drop `timeZoneName` and add the zone separately. Then add a render test of the confirmation and manage views.

### QA-023: Five operator desks never load (Schedules & flights, Inventory & fares, Payments & refunds, Manifest entry & audit, Settings & readiness)
- **Area:** dashboard
- **URLs:**
  - `/dashboard/platform/schedules`
  - `/dashboard/platform/inventory`
  - `/dashboard/platform/payments`
  - `/dashboard/platform/manifests`
  - `/dashboard/platform/settings` (its Connections section)
- **Steps:** Sign in as the full-permission initial administrator and open each desk, before or after launch setup.
- **Expected:** Each desk lists its records, for example the AV 101 dated flight, its inventory bucket and the settlement connection.
- **Actual:**
  - Each shows "This section could not be loaded. Check your access and try again." The access hint is wrong: this role has every permission.
  - Running the page's query directly with the operator session returns `KS_USER_INPUT_ERROR` "Input error: Only a string can be passed to id filters".
  - **Consequences:**
    - An operator can't see or add dated flights. `provisionDatedFlight` lives only on the Schedules desk.
    - An operator can't change seat authorization or open and close sales.
    - An operator can't review payments or manifests.
- **Cause:** with no cursor in the URL, each desk sends `…CursorId: cursor ?? ''`. The query then filters a second alias with `{ id: { equals: "" } }`, which Keystone rejects, and the whole query fails. Present since `c898eaf`; rounds 1 and 2 couldn't sign in to see it.
- **Likely files:** `features/platform/screens/Canonical/PlatformDeskPages.tsx`
  - Line 241: `flightCursorId`, in `networkDataForInventory`.
  - Line 283: `flightCursorId`.
  - Lines 391 and 395: `paymentCursorId`, `evidenceCursorId`.
  - Line 473: `auditEventCursorId`.
  - Line 523: `providerConnectionCursorId`.
  - The matching query strings, e.g. `features/platform/lib/provider-connection-worklist.ts`. Fix by skipping the cursor alias, using `@include(if:)` or a separate query, when there is no cursor.

### QA-024: There is no UI path to mark a booking paid, so nothing can be ticketed, checked in or boarded
- **Area:** dashboard
- **URL:** `/dashboard/platform/bookings`
- **Steps:**
  1. On booking 865CD0, enter a Settlement reference and click **Record payment**.
     → "Approved manual settlement evidence is required."
  2. Fill Ledger source and SHA-256 digest and click **Submit evidence**.
     → "Imported ledger reference, source, SHA-256 digest, and amount are required." (the reference comes from the Payment row's field; see QA-029)
  3. Fill the Payment row's Settlement reference as well, then **Submit evidence**.
     → "An externally imported settlement ledger entry is required."
- **Expected:** A merchant who has received money, by bank transfer or at the counter, can record it from the dashboard. Then **Issue ticket**, seat assignment, check-in and boarding become available. E-commerce's manual payment provider lets an operator mark an order paid from the order page.
- **Actual:**
  - The only way to create the required SettlementLedgerEntry is an HTTP POST to `/api/integrations/settlements/<connectionKey>` with the machine credential from onboarding. No dashboard screen does this, and the help text never mentions it.
  - Every booking therefore stays Pending / Unpaid / Not Ticketed and expires after 24 h.
  - Ticketing, the seat map, check-in, boarding passes, the gate and manifest flows, and refunds are unreachable for a real operator. QA did not call the API, because the brief allows test data only through the app's own UI.
  - Related to round-1 QA-004 (online payment, open by decision), but this is the manual path, which the launch scope ("externally evidenced manual settlement") says is supported.
- **Likely files:**
  - `features/platform/components/BookingDesk.tsx:81-95` (`submitEvidence`) and `capture`
  - `pages/api/integrations/settlements/[connectionKey].ts`
  - `features/keystone/mutations/airlineWorkflows.ts` (`submitManualPaymentEvidence`)
  - **Fix direction:** an operator-facing "Import settlement entry" form on the Payments desk that calls the same import logic under the operator session, with maker/checker kept.
